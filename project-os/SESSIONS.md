- **Knowledge transfer:** NestJS's `ConfigModule.forRoot()` and the Prisma CLI resolve `.env` relative to `process.cwd()`, which is `apps/api/` when launched via the root `npm run dev:api` workspace script — the top-level repo README's `cp .env.example .env` instruction (root-level) is misleading; `.env` must also exist inside `apps/api/`. `apps/web` needs its own `.env.local` for `NEXT_PUBLIC_API_URL` — Next.js doesn't read the API's `.env`. Supabase's dashboard connection-string UI renders the password inside a bracketed chip (`[actual-password]`) that looks like a placeholder but isn't — and the password needs URL-encoding (`!` → `%21`, `^` → `%5E`, etc.) before it's usable in a Prisma connection string. The Suite's Prisma schema names its migration-connection env var `DIRECT_DATABASE_URL`, not the `DIRECT_URL` name Supabase's own docs suggest — match whichever name `schema.prisma`'s `datasource` block actually declares.
